# Scout browser helper

Scout’s Manifest V3 helper keeps reviewed profile details, exact recurring answers, and selected documents in reach of an application form. Filling starts only when you ask. Workday runs in a bounded, opt-in session; you review each page and submit every application yourself.

## Install the unpacked extension

The helper is distributed as the local `extension/` folder in this workspace. To use it, choose a compatible Chromium-based browser with Manifest V3 extension support, enable its developer or unpacked-extension mode, and load that folder. Sign in to Scout and use the helper in the same browser profile. The Mercer pages were investigated in Codex’s in-app browser, but the extension was not loaded or tested there because the available browser controls do not verify MV3 extension loading.

In the popup, choose **Set up**, enter Scout’s exact origin, then choose **Connect**. Approve access only to that Scout address when the browser asks. Scout’s local development address is often `http://127.0.0.1:4173`; use the address shown by your running server. Sign in to Scout at that address before connecting.

The extension reads the account-bound application profile and saved answers through Scout’s same-origin API. Disconnecting clears local profile data, answer drafts, saved documents, and pending submission logs. If the connected Scout account changes, the previous account’s local data is cleared before the new account is used.

## Review your profile and answers

The extension popup contains editable contact, location, link, eligibility, preference, education, and experience fields. Work Experience has an editable row count, staged locally as **1** on first use. On first use it also stages local preferences for Canada, Mobile, the exact phone-code label **Canada (+1)**, LinkedIn referral, previous-employer **No**, and preferred-name **Yes**. Certifications and preferred-name text begin blank. These are local extension defaults; they are not Scout account defaults. Existing saved values take priority, and a one-time starter merge does not re-seed fields after you intentionally clear them. **Save profile** keeps edits in this browser; **Sync with Scout** is a separate action.

The popup also offers editable Mercer-specific drafts for the answer facts supplied for this application flow. They are scoped to the Mercer Workday origin and `en-US`; the current-student question remains unanswered. Choose **Save reviewed answers** once to save the drafts you have reviewed together. They then become active for exact prompt matching in this browser. They are not uploaded to Scout until you separately choose **Sync with Scout**. Same-prompt answers with different scopes remain separate, so a Mercer-specific choice can take priority on Mercer without replacing a global answer. Exact prompt matching preserves punctuation and does not infer an answer from nearby profile fields.

For an unfamiliar question, the popup can save a reviewed exact text, single-choice, multi-choice, or boolean response with optional site, country, and locale scope. The helper applies only an exact prompt and exact visible choice. A required marker, an employer default, a nearby answer, or a different country never creates a saved response. Passwords, CAPTCHA and bot-trap controls, security codes, account creation, and payment fields stay manual. The per-application Workday terms checkbox and the federal/reference agreement stay manual every time, even if a matching answer is saved.

The original resume document is not imported into Scout’s structured profile. Choose a PDF or DOCX resume and/or cover letter in the popup; the combined local document limit is 5 MB. **Remove stored resume** and **Remove stored cover letter** clear only their respective browser-local file. Documents are not synced to Scout.

## Fill an application

For Greenhouse, Lever, and Ashby, choose **Check page**, review the report, then choose **Fill blank fields**. Existing meaningful values stay untouched. The helper uses visible field labels, names, IDs, autocomplete metadata, and exact saved answers. Unsupported pages and embedded application frames remain manual.

Workday sign-in and account-creation gates remain manual. On an application page, choose **Start Workday session** and grant the exact employer-origin permission if requested. This explicit action can replace Workday’s preselected Country or Phone Country Code with an exact saved preference; later trusted edits are protected. The session expires after 30 minutes, fills newly rendered controls as they appear without relying on a fixed step order, and can use profile or saved-answer changes made in the popup without restarting. **Stop Workday session** ends it early. Scout does not click page navigation controls.

Country-scoped answers use the job country, not the applicant’s residence country. Scout recognizes `CAN`/Canada or `USA`/United States in the same Workday job URL, or one explicit country in that exact posting’s visible location nodes. It ignores `en-US` locale, state/province names, the profile address, job-description prose, and titles such as “US Developer.” Mixed-country or unresolved location evidence stays unknown for manual review. A country choice in the popup is bound to that job and takes priority, including an explicit blank selection.

Automatic written drafting is on by default for eligible professional narrative fields. When same-job context is missing, Start may open that exact Workday posting in an inactive temporary tab to read visible location nodes for country scope and, when needed, its visible posting header, locations, and bounded job description; it then closes the tab. It verifies the employer origin and job key and never reads the application page as job-description context. If the matching posting or description is unavailable, the question stays manual. Luna drafts are inserted only into a still-blank eligible response after the account, application, session, profile, saved answers, and question are rechecked. Generated text remains editable in Workday; review every answer yourself before you submit. The server does not save these drafts as reusable answers.

The live Mercer investigation observed all five application steps:

- **My Information (1/5):** legal name, address, province, country, phone number/type/code, referral source, preferred-name toggle and fields, and a combined previous-employee/student/current-MERC-worker control. The saved previous-employer **No** applies to direct employer-history Yes/No questions at any employer. You also explicitly confirmed No for the full observed compound template, so the same tightly matched Workday template can be answered for another named employer. It does not answer a student-only question. The referral menu showed top-level categories External Website, Mercer, Other, Referral, and Social Media; the exact LinkedIn leaf option and selection hierarchy were not verified. The helper uses an exact label match and leaves it for review if the matching option is unavailable. Preferred-name first and last names stay blank until you enter them and never fall back to legal names. Workday’s initial Country and Phone Country Code defaults may be replaced by your saved preferences when you start the session.
- **My Experience (2/5):** Certifications has an **Add** control and is left empty. A single shared, multiple-file Resume/CV widget was observed. When it has no existing uploads, the helper can attach both stored resume and cover letter together through its hidden native file input. If the widget already shows an uploaded file, the helper leaves the entire widget alone. The page also requests three professional references, but no reference entry control was confirmed; references stay manual.
- **Application Questions (3/5):** dynamic `primaryQuestionnaire--*` buttons are single-choice listboxes inside fieldsets; the direct legend supplies the question. A salary textarea uses the same dynamic field pattern. The helper discovers the current controls and does not hardcode question IDs or step order. Only exact, matching saved answers apply. The current-student response is unknown and stays blank. The federal eligibility/reference declaration remains manual for every application.
- **Voluntary Disclosures (4/5):** observed custom pickers cover veteran status, Hispanic/Latino, and gender; the Race Category group uses native checkboxes. Exact scoped Mercer answers can fill only their matching prompts and option labels. The Certification checkbox is an application-specific agreement and always remains manual.
- **Review (5/5):** read-only summary. The helper reports this page as unsupported and stops before the separate **Submit** control.

The Semtech investigation confirms the adapter also works with a Canadian job whose application route is `en-US`. The listing identifies the role as CAN—Richmond, BC; the language locale does not imply US eligibility or answer scope. All six steps were inspected in Codex’s in-app browser:

- **Autofill with Resume (1/6):** the `resumeUpload` widget has one hidden, non-multiple file input and a visible Select file button. Its instructions allow DOC, DOCX, HTML, PDF, and TXT up to 5 MB. The adapter recognizes this observed parser shape and attaches the stored resume only; it does not put the cover letter in a single-file resume control. The IAB accepted a synthetic test PDF and showed Workday’s successful-upload state. Native extension execution was not available for that check.
- **My Information (2/6):** the previous-employer question is a native Yes/No group and uses the saved general previous-employer preference. The referral control is a single-choice button with Agency, Corporate Website, Indeed, LinkedIn, Recruiter, and Semtech Employee Referral options; this differs from Mercer’s searchable multi-select. The adapter chooses only one exact option for the button and leaves Mercer’s multi-select behavior intact. The page showed Canada, Mobile, and Canada (+1) selections, plus an optional province/territory picker with all 13 Canadian provinces and territories. Preferred-name fields remain separate from legal names and stay blank until supplied. Only clearly labeled Country, Country/Region, address-country, and residence-country prompts use the profile’s residence country; other country questions are left for review. Canadian location, locale, and address do not fill citizenship, nationality, country of birth, authorization, sponsorship, or enrollment answers. The global sponsorship preference is not used for automatic fills; only a reviewed exact-prompt answer that matches the current scope can be reused.
- **My Experience (3/6):** observed repeatable sections include Work Experience, Education, Languages, and Websites. The editable Work Experience count defaults to one; when Start finds extra Work Experience panels, it removes them from the end using only a unique, row-scoped **Delete** control, and verifies each panel disappears before continuing. The observed remaining first panel has no Delete control, so a requested count of zero may leave one row with a warning. Education, Languages, and Websites are never trimmed. Profile records map by row index, existing populated text/date values remain untouched, and rows are added only when the configured section count needs them. Dates accept `YYYY-MM` or year-only without inventing a month or day. The user’s “currently work here” default is explicitly off for new or unstated rows, while company-specific saved choices and later edits are preserved. Chinese and English use exact visible language options, a fluent checkbox, and exact proficiency labels; blank website starter slots do not create Workday rows. Extra Education, Language, and Website rows are kept and reported. Field of Study uses the observed closed search input: the helper enters the saved query, opens results with Enter, chooses only one exact visible catalog label, and verifies the matching selected-item tag. Missing or ambiguous results stay for review. Degree and language menus are also selected only by exact visible labels. No calendar is opened; Add and Delete controls are guarded against default form submission.
- **Application Questions (4/6):** dynamic questionnaire buttons are single-choice listboxes associated with their visible prompt; the current page asks about work eligibility in the job country, sponsorship, location/relocation, CAD salary range, a Semtech-related person, minimum education, and semiconductor/electronics/manufacturing experience. Two required essay prompts ask about relevant experience and tools or systems. Eligible blank professional essays can receive automatic Luna drafts using the same-job public description and saved professional profile. No answers are inferred from Canadian residence, an `en-US` locale, or the salary “Negotiable” text draft when the option list does not contain an exact match. The values provided for this Canadian listing are scoped to Canada and remain editable in the extension before saving.
- **Voluntary Disclosures (5/6):** the observed page has a required terms-and-conditions checkbox covering background checks and data release. This binding agreement stays manual for each application.
- **Review (6/6):** Workday shows a read-only application summary and a separate final **Submit** control. The adapter stops on this page; it never clicks Submit or marks the application submitted.

Selectors and custom controls are grounded only in the tenant observations listed here and the live Mercer observations above. Generic native fields may be recognized elsewhere, but unobserved Workday custom widgets remain unverified. Review every changed field and attachment. ## Submit and log yourself

Scout never advances a Workday step, clicks a final submit control, or submits an application. After you submit, choose **I submitted this application** to create the application log. A confirmation page by itself does not log anything. The helper can also detect a strong new confirmation only after it observes a trusted user submission event; a pre-existing confirmation phrase is not enough. Automatic logging requires a connected, verified Scout account. If Scout is unavailable, a confirmed log stays queued locally and retries when Scout is available.

Workday session start stores the original application URL and the reviewed employer metadata for manual logging after popup dismissal or same-origin confirmation navigation in the same tab. The popup shows the original URL and lets you correct company, role, or location before logging; it never uses the Workday step heading as a role title. Navigating to another job clears the prepared context, including SPA route changes. A manual log still requires your explicit click and a connected, verified Scout account.
